Run `/analyze` for open journal positions, then validate and save results.

## Mode detection

Check `$ARGUMENTS`:
- **If a TICKER is provided** (e.g. `/analyze-journal AVGO`) → **Single-ticker mode**: analyze only that ticker
- **If empty** (e.g. `/analyze-journal`) → **All-tickers mode**: analyze every unique open ticker

> ⚠️ **Pro plan users**: Use single-ticker mode to avoid hitting usage limits. Run one ticker per session.

---

## Step 1 — Read journal

Read `private/journal.json`. Collect all trades where `status == "open"`, extract unique tickers (deduplicate).

**Single-ticker mode:** Confirm the given ticker exists as an open position. If not found, stop and say:
> "`<TICKER>` ไม่มีใน open positions — ตรวจสอบ journal อีกครั้ง"

Show the user which tickers are being skipped this session:
> "Session นี้: analyze **AVGO** · เหลือ RXRX, FLY, ONDS สำหรับ session ถัดไป"

---

## Step 2 — Check report freshness (staleness gate)

Before analyzing, check if a fresh report already exists for each ticker.

**Run this bash command to find the latest report date per ticker:**
```bash
ls web/data/reports/<TICKER>_*.json 2>/dev/null | sort | tail -1
```

Parse the date from the filename (`<TICKER>_YYYYMMDD.json`) and compare to today:

| Report age | Action |
|------------|--------|
| **≤ 3 days** | ⏭ **Skip** — reuse existing report, save tokens |
| **> 3 days or missing** | 🔄 **Analyze** — run full `/analyze` workflow |

Show the staleness check result before proceeding:
```
📋 Staleness check:
  AVGO → last report: 20260623 (7 days ago) → 🔄 WILL ANALYZE
  RXRX → last report: 20260629 (1 day ago)  → ⏭ SKIP (fresh)
  FLY  → no report found                    → 🔄 WILL ANALYZE
  ONDS → last report: 20260630 (today)       → ⏭ SKIP (fresh)
```

**Only run `/analyze` for tickers marked 🔄.** For skipped tickers, proceed directly to journal validation using the existing report price.

---

## Step 3 — Analyze stale ticker(s)

For each ticker marked 🔄 — run the full `/analyze` workflow from CLAUDE.md:
- Load the `xvary-stock-report` skill
- Research live data (price, catalyst, analyst targets, comparable cases) BEFORE writing
- Save JSON to `web/data/reports/<TICKER>_<YYYYMMDD>.json`
- Run `node scripts/validate-reports.mjs` after saving

If **all tickers are fresh** (all skipped) → skip directly to Step 5 (journal validation). No commit needed.

---

## Step 4 — Commit and push (only if new reports were generated)

Skip this step entirely if all tickers were fresh (no new JSONs written).

```bash
git add web/data/reports/
git commit -m "report: analyze-journal <TICKER(s)> <YYYYMMDD>"
git push origin main
```

---

## Step 5 — Run journal validation

Load the `journal-validator` skill and validate **all open tickers** (both freshly analyzed and skipped ones) against current prices.

For each ticker produce:
- `verdict`: `"HOLD"` | `"CUT"` | `"WATCH"`
- `thesisIntact`: true/false
- `stopBreached`: true if current price ≤ plannedSL
- `atRisk`: true if current price is within 3% above plannedSL
- `summary`: 1–2 sentence status
- `action`: one-line recommendation
- `color`: `"green"` | `"yellow"` | `"red"`

---

## Step 6 — Save validation results

Read existing `private/journal-validation.json` if it exists — **merge** the new results into it (do NOT overwrite results for tickers not analyzed this session). Update `generatedAt` to now.

```json
{
  "_note": "Journal validator results — generated by /analyze-journal. Local only, never committed to git.",
  "generatedAt": "<ISO timestamp>",
  "results": {
    "AVGO": { "verdict": "WATCH", "thesisIntact": true, "stopBreached": false, "atRisk": false, "summary": "...", "action": "...", "color": "yellow" },
    "RXRX": { "verdict": "HOLD", ... }
  }
}
```

This file is read by the web journal page at `/journal` to show the validator section on each open trade.
